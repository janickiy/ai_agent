# Архитектура

## Поток данных

```text
Laravel Scheduler
  -> SourceMonitor
     -> SafeHttpClient
     -> RssParser
     -> collector_source_items (discovered)
     -> Redis / ProcessSourceItem
        -> ArticleExtractor
        -> AIProvider (rules или GigaChat)
        -> точная и семантическая дедупликация
        -> валидатор неизменности
        -> publishing_publication_posts (ready)
```

Каждый обнаруженный URL получает устойчивый SHA-256. Работа с готовым постом выполняется транзакционно. Повторная доставка queue job возвращает существующую строку, если она уже создана.

## Границы модулей

- `app/DTO` — неизменяемые объекты данных для операций создания и изменения.
- `app/Repositories` — базовый CRUD-репозиторий и его общий интерфейс.
- `app/Modules/Admin/Repositories` — репозитории административного модуля.
- `app/Modules/NewsMonitor/Repositories` — доменные репозитории каталогов, pipeline и системных данных.
- `app/Modules/NewsMonitor/Services` — прикладной pipeline, сбор, извлечение, нормализация и безопасность.
- `app/Modules/NewsMonitor/AI/Contracts` — независимый от поставщика контракт.
- `app/Modules/NewsMonitor/AI/Providers` — правила и GigaChat.
- `app/Modules/NewsMonitor/Models` — модели каталогов, кандидатов, анализа, дублей, журналов и готовых постов.
- `app/Modules/Admin` — контроллеры, Requests и административные сценарии.
- `app/Jobs` — повторяемые фоновые задания.

## CRUD и передача данных

Административный CRUD использует последовательность `FormRequest -> DTO -> Repository -> Eloquent`.
Контроллер отвечает за авторизацию и HTTP-ответ, DTO — за нормализацию разрешённых полей,
а репозиторий — за чтение и запись модели. Публичные методы `create` и `update` базового
репозитория принимают только наследников `DataTransferObject`; передача произвольного массива
из контроллера исключена контрактом.

Фоновые сценарии используют тот же контракт: `SourceMonitor` и `NewsPipeline` создают и изменяют
источники, материалы, результаты анализа, дубли, публикации и журналы только через профильные DTO
и репозитории. Сложные выборки, идемпотентные `upsert`/`firstOrCreate` и массовая очистка также
инкапсулированы в репозиториях.

Связанные изменения выполняются атомарно. Например, `SourceRepository` сохраняет источник и
синхронизирует его тематики в одной транзакции. Запись настроек и аудита также проходит через
профильные репозитории; секреты AI-провайдеров не включаются в публичное представление DTO.

## Решения по безопасности

Контент страниц считается недоверенным. HTML-скрипты не выполняются. Текст источника передаётся модели только как пользовательские данные, а системная инструкция запрещает ему изменять контракт ответа.

Загрузчик проверяет схему, DNS и каждый редирект, блокирует непубличные IP и ограничивает размер ответа. Изображение не скачивается автоматически: хранится только публичный URL или `NULL`.

Административные маршруты защищены цепочкой `auth`, `active_user`, `admin_access`; изменяющие действия дополнительно проверяются через Gates и CSRF.

## Расширение

Новый AI-провайдер реализует `AIProvider` и регистрируется в `NewsMonitorServiceProvider`. Новый discovery-формат добавляется перед созданием `SourceItem`; контракт последующих этапов не меняется. Поля таблицы `publishing_publication_posts` не зависят от внешнего канала доставки.
